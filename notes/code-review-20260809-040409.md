### QC-H1 · High — QC triage notes never reach the auditor: `qc_map` is computed and never passed

`scripts/synthesis/register_audition.py:439` — `main()` computes `qc_map` (line 394) and
prints *"N clips carry a QC finding — all queued for the ear"*, but calls
`register_audio_dir(audio, slug, existing_ids, fields, args.dry_run)` without `qc=qc_map`.
The parameter defaults to `None` (line 327), so the `row["note"] = qc[cid]` branch
(lines 352–356) is dead code; `git log -S "qc=qc_map"` is empty — it has never been wired
since QC triage landed 2026-07-31. **Verified in source by the reviewer.**

Failure scenario: a tail-truncated clip is queued with a blank note; the auditor hears a
clean-sounding mid-sentence ending and scores it 5 — exactly the
`the-return_nar_0051_doc_MOS` failure the notes were written to prevent. Every carefully
worded triage note ("stops early — LISTEN TO THE END", the pause/head/edition-gap notes)
has been discarded for nine days; `qc_noted` has always printed 0 and nobody noticed.
`qc_flags.txt` still carries the ids, so *coverage* survives via `pick_audit_subset
--flags`; the *guidance* does not. STATE.md's claim "findings attach as direction-aware
notes, never verdicts" is **NOT AS CLAIMED** — the notes half has never operated.
No test covers `main()`'s wiring.

### QC-H2 · High — the C-M1 "deferral is revisable" fix is unreachable code

`scripts/synthesis/pick_audit_subset.py:355–356` filters `camp` to
`r["status"] == "unaudited"`; `by_group` and therefore every contributor to `keep_ids`
(including the `--flags` intersection at line 366) draws only from those rows. The
requeue branch at line 445 — `elif r["id"] in keep_ids and r["status"] == "deferred"` —
can therefore never fire: an id in `keep_ids` is by construction an unaudited row's id.
**Verified in source by the reviewer.**

Failure scenario: a clip deferred by an earlier `select` and QC-flagged by a later
`qc_engine_defects` pass stays deferred forever — precisely the bug the eleven-line C-M1
comment above the branch (lines 434–444) records as fixed. The guard test
(`tests/test_audit_sampling.py:55–64`) greps for the source strings, so it passes over
the dead branch. Fix shape: build `by_group` from `status in ("unaudited", "deferred")`
— `mutate` already distinguishes the two.

### QC-M1 · Medium — the em-dash repeats the hyphen bug `b6d29b2` fixed

`scripts/synthesis/synth_common.py:188–189` — `norm()` does `re.sub(r"[-–]+", " ", …)`
then strips everything else. The class covers hyphen-minus and en-dash but not em-dash
(`—`, U+2014), so em-dashes are *deleted*, fusing tokens: "Well—I suppose" →
`['welli', 'suppose']` against Whisper's `['well', 'i', …]` → fabricated head/edge loss.
**Verified by the reviewer.** `tail_ok` is a HARD gate on this measure, em-dash is
ubiquitous in SE/PG epub prose (the book lane's main text source), and `b6d29b2`'s own
rationale — "every other text path treats `-` as a separator" — applies verbatim.
`qc_gate._words` (the WER path) handles em-dash correctly; only `edge_loss` diverges.

## Training-lane findings

### TR-M1 · Medium — the merge's digit filter is ASCII-only and runs pre-unidecode, so Unicode digits ship D-M3 through the fix

`scripts/merge_emilia_corpus.py:251` — `if re.search(r"[0-9]", text): drop("digits", …)`
runs on the raw caption, but `op_g2p.phonemize` (`matcha/text/op_g2p.py:390–401`) first
runs `convert_to_ascii` (unidecode), which maps full-width digits (`１００`),
superscripts (`²`) and vulgar fractions (`½` → `1/2`) to ASCII digits — which
`_TOKEN_RE` then silently deletes. A caption "chapter Ⅻ" passes the filter, the
tokenizer deletes the numeral, and the clip trains with a transcript missing words the
audio speaks — exactly the D-M3 defect the drop exists to prevent.
`tests/test_label_derivation.py::test_no_merged_row_carries_a_digit…` checks the
*phonemes* for digits, which by construction can never fire (they were deleted). The
derive lane uses `any(c.isdigit() for c in text)` (`derive_vat_corpus.py:670`) — a third
digit semantics; neither lane catches `½`. Fix: check the post-`convert_to_ascii` text,
in one shared place beside the tokenizer that does the deleting.
